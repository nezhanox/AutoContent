# AI Content Factory — міні-гайд

Що це: Laravel/Filament-застосунок, який генерує faceless короткі відео
(сценарій → сцени → озвучка → b-roll → субтитри → рендер → перевірка якості)
і публікує їх (поки що заглушка) в TikTok/YouTube/Instagram/X.

## 1. Підняти локально

```bash
# Postgres + Redis
docker compose up -d postgres redis

# .env: скопіювати з .env.example і виставити реальні ключі
cp .env.example .env    # якщо ще нема
php artisan key:generate
php artisan migrate

# Веб-сервер (адмінка на http://127.0.0.1:8080/admin)
php artisan serve --port=8080

# Черга — ОБОВ'ЯЗКОВО перезапускати після будь-якої зміни коду
# (Laravel-воркер не перезавантажує PHP-класи на льоту)
php artisan queue:work --queue=render,whisper,default --tries=3 --timeout=300
```

Дефолтний логін (з сідера `DatabaseSeeder`): **admin@autocontent.test / password**.

Ключі, які потрібні в `.env` для реальної генерації:
- `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` — хоч один LLM-провайдер
- `ELEVENLABS_API_KEY` — озвучка
- Whisper (субтитри) і ffmpeg (рендер) мають бути встановлені локально
  (`WHISPER_PYTHON_BINARY`, `FFMPEG_BINARY` в `.env`)

## 2. Як згенерувати відео (новий, спрощений спосіб)

1. Зайти в **Content Projects** → створити або відредагувати канал:
   вибрати "Publish platforms" (чекбокси) і "Default voice" (голос ElevenLabs).
2. Зайти в **Videos** → кнопка **"Generate Video"** зверху.
3. Вибрати канал, вписати тему одним реченням — і все. Система сама:
   - згенерує ідею через LLM,
   - напише сценарій,
   - розкладе на сцени,
   - озвучить,
   - підбере b-roll (з локальної медіатеки — **автоматичного пошуку в
     інтернеті ще нема**, треба заздалегідь завантажити відео/фото і
     затегати їх у **Media Assets**, щоб теги збігалися зі словами з
     `visual_query` сцен),
   - згенерує субтитри (Whisper),
   - відрендерить фінальне відео (ffmpeg),
   - перевірить якість.

Усі 7 етапів ідуть автоматично одне за одним — вручну тиснути кнопки
більше не треба (хоча старі окремі кнопки на кожному етапі й далі є, про
всяк випадок).

## 3. Дашборд і що робити, якщо щось впало

На сторінці **Videos** з'явилась колонка **Stage** — показує, на якому
етапі відео зараз, або на якому етапі і чому воно впало
(`Failed: Voiceover`, `Quality check failed`, `Rendering (retry if
stalled)` тощо).

Якщо рядок червоний ("Failed") — з'являється кнопка **Retry**: вона сама
скидає статус і перезапускає саме той етап, що впав, не чіпаючи вже
готові попередні етапи.

Кнопка **View** (іконка ока) відкриває картку відео з попереднім
переглядом кожного етапу: текст сценарію, список сцен, посилання на
прослуховування озвучки, текст субтитрів, посилання на фінальне відео.

## 4. Чого поки немає (свідомо не робили)

- **Реальний пошук b-roll в інтернеті** (Pexels/Pixabay/AI-генерація) —
  зараз лише локальна медіатека з тегами. Довелось вручну підбирати й
  завантажувати відео для тестів.
- **Реальна публікація** в соцмережі — `FakeSocialPublisher`, публікація
  не йде далі бази даних. Платформи в налаштуваннях каналу лише
  зберігаються, нічого нікуди не постять.
- **Шаблони стилю з прикладних відео**, **джерела контенту** (книги,
  YouTube-канали, новини, історії з Reddit/X, історичні теми) — окремі
  майбутні напрямки, ще не почато.

## 5. Відомі дрібні обмеження (не блокують, але варто знати)

- Прев'ю-поля на сторінці відео (`VideoForm`) рендеряться і на
  Create/Edit формах теж (не тільки View) — нешкідливо, просто зайве.
- Посилання на озвучку/відео — тимчасові підписані URL (діють 30 хв),
  після цього треба перевідкрити сторінку відео, щоб отримати нове
  посилання.
- УІ-клацання вручну в цій сесії не перевірялось (немає підключення до
  Chrome) — але весь новий UI покритий Livewire-тестами, що рендерять
  реальні компоненти (не моки), плюс наскрізний інтеграційний тест усього
  7-етапного ланцюга.
